# ClipPay UX 提升规划：从黑客松 Demo 到专业平台

> 版本 v1 · 2026-10-25 · 作者：产品经理 / UI 设计（Claude，代拟）
> 状态：规划，待确认后分阶段实施。每项有编号（UX-x.y），实施时在第 12 节勾选。
> 关联：[improvement-plan.md](improvement-plan.md)（产品与工程路线）· 在线版本 <https://clippay.umesok.workers.dev>

## 0. 目标

**一句话：** 让品牌方第一眼就敢把预算放进来，让创作者三步之内拿到第一笔钱，让评委和投资人觉得这是一个正在运营的平台，而不是一个合约 Demo。

"看起来专业"拆成四个可以检验的标准：

| 维度 | 标准 | 怎么验证 |
|---|---|---|
| **可信** | 每一个金额都能追溯到链上记录；资金去向说得清；平台身份明确 | 主要页面上的每笔付款都有"链上凭证"链接；有安全说明页 |
| **清晰** | 用户不需要懂 Stellar、合约或 XLM 就能完成任务 | 5 秒测试：新访客能说出这是什么、为谁服务；主界面不出现 `settle`、`contract`、裸地址 |
| **精致** | 视觉统一，有品牌识别；加载、空、错误状态都经过设计 | 组件全部来自设计系统；没有"Loading…"纯文本；Lighthouse 性能 ≥ 85 |
| **高效** | 关键任务步骤少、反馈即时 | 创作者从打开链接到提交 ≤ 3 步、≤ 60 秒；品牌建活动 ≤ 3 分钟 |

## 1. 现状诊断

基于 2026-10-25 线上版本的走查（首页、活动卡、活动详情、建活动、钱包面板，桌面 + 375px 手机宽度）。

| # | 问题 | 位置 | 影响 | 严重度 |
|---|---|---|---|---|
| D1 | **品牌识别弱**：logo 是紫色方块里的 ▶，系统字体，单一靛蓝色，没有插图或产品画面 | 全站 | 像模板站，难以留下印象 | 高 |
| D2 | **首页像开发者 Demo**：首屏只有标题和两个按钮；指标条用原始 `XLM` 单位；"How it works"三段纯文字 | `/` | 首屏没有展示产品本身，价值主张不够具体 | 高 |
| D3 | **地址裸露**：品牌显示为 `by GCTP…FBZH`，创作者表格全是 `GBZG…T2DO` | 卡片、详情、钱包 | 没有"人"的感觉，像区块浏览器 | 高 |
| D4 | **活动卡同质、信息少**：没有品牌头像、平台（YouTube Shorts / TikTok）、每人最高可赚、截止紧迫感 | 活动列表 | 创作者无法快速判断值不值得做 | 高 |
| D5 | **把内部操作暴露给所有人**："Verify views now"对每个访客可见；四个统计卡权重相同 | 活动详情 | 显得半成品；重点不突出 | 中 |
| D6 | **建活动是一张长表单**：时长用"Open for (hours)"；简报必须是外部链接；签名前没有总费用确认和预览 | `/new` | 品牌方不放心，容易填错 | 高 |
| D7 | **状态反馈简陋**："Loading campaigns…"纯文本；toast 只有一句话；交易过程（签名 → 上链 → 确认）没有进度 | 全站 | 等待时不知道发生了什么 | 中 |
| D8 | **缺少创作者主页**：提交后的状态（待核验 / 暂缓 / 已付款）只能在活动表格里找到自己那一行 | 无 | 创作者没有"我的收入"概念，复访动力弱 | 高 |
| D9 | **钱包面板功能堆叠**：余额、两种提现、退出挤在一个下拉面板；没有交易记录 | 钱包 | 用户不确定钱到哪了 | 中 |
| D10 | **测试网和平台身份不明确**：只有页脚一行小字；没有关于、FAQ、条款、安全说明 | 页头、页脚 | 削弱可信度；评委不清楚这是 testnet | 中 |
| D11 | **术语混杂**：`settle`、`contract`、`XLM / 1k views`、`passkey wallet` 直接出现 | 全站文案 | 非加密用户看不懂 | 中 |
| D12 | **性能**：首屏主 JS 570 KB（未压缩），包含钱包和 anchor 相关代码；活动列表在浏览器里对每个活动单独发 RPC 请求 | 全站 | 首屏慢；活动多了会更慢 | 中 |
| D13 | **分享卡片缺失**：活动链接发到 X / Telegram 没有预览图 | 活动详情 | 品牌最常见的分发场景体验差 | 中 |
| D14 | **手机端**：顶部导航挤；创作者表格在窄屏上需要横向压缩 | 375px | 创作者大多用手机 | 中 |

**已经做得好的、要保留的：** 明暗主题、无障碍基础（axe 0 个严重问题、弹窗焦点管理）、首页实时指标、活动预算进度条、暂缓原因展示、免手续费的 passkey 登录。

## 2. 设计原则

1. **先讲钱，再讲技术。** 用户关心"我能赚多少、什么时候到账"，不关心链和合约。技术细节放在"了解更多"和链上凭证里。
2. **每个数字都可验证。** 金额旁边可以点开链上凭证。这是 ClipPay 相对中介平台的核心差异，要在界面上显性化，而不是藏在页脚。
3. **角色分明。** 品牌和创作者的目标完全不同，导航、首页入口、主页分开设计，不让一方看到另一方的操作。
4. **一屏一件事。** 复杂流程（建活动、提现）用分步流程；每一步只有一个主按钮。
5. **安静的专业感。** 克制的配色、清晰的层级、等宽数字、充足留白；动效只用来说明状态变化。

## 3. 品牌与视觉系统

### 3.1 品牌识别（UX-1.1）

- **Logo**：保留"播放"的意象，与"支付 / 流动"结合。方向：圆角方形内一个播放三角，三角右下角延伸出一条向上的增长线，表示"播放 → 收入"。提供图形标、文字标、组合标三种，以及单色版本。
- **Favicon / App icon**：用图形标，16/32/180/512 各尺寸，包括 `apple-touch-icon` 和 `manifest.webmanifest`。
- **社交分享图**：默认 OG 图 1200×630（标语 + 产品截图），每个活动单独生成（见 UX-3.3）。

### 3.2 颜色（UX-1.2）

保留现有 token 架构（`:root` + 暗色覆盖），扩展为完整色板：

| Token | 用途 | 方向 |
|---|---|---|
| `--brand-500/600/700` | 主按钮、链接、焦点 | 现有靛蓝 `#5b5bf0` 微调为更深、更稳重的蓝紫（如 `#4f46e5` 一档） |
| `--money-500` | 收入、已到账、正增长 | 偏青的绿色，与"成功"状态区分开，专用于金额 |
| `--neutral-0…950` | 背景、表面、边框、文字 | 11 级冷灰，替代现在零散的 `--bg/--surface/--border/--muted` |
| `--ok / --warn / --danger / --info` | 状态 | 现有值保留，补 `--info` |
| `--testnet` | 测试网徽标 | 琥珀色，全站唯一用途 |

规则：同屏强调色只有一个；金额用 `--money`，状态用语义色，不混用；所有组合保持 WCAG AA（继续用 axe 校验）。

### 3.3 字体与数字（UX-1.3）

- 正文和标题：**Inter**（可变字重），通过 npm 包自托管，不依赖第三方 CDN。标题字距收紧 −0.02em。
- 数字、金额、地址：**JetBrains Mono** 或 Inter 的 `font-variant-numeric: tabular-nums`。金额统一右对齐、等宽，列表里的数字不会跳动。
- 字号阶梯：12 / 13 / 15 / 17 / 20 / 24 / 32 / 44 / 56，行高 1.5（正文）、1.15（大标题）。

### 3.4 间距、圆角、阴影（UX-1.4）

- 4px 基准：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 圆角：输入框和按钮 10px，卡片 16px，弹窗 20px，徽标全圆角。
- 阴影 3 级：卡片（几乎不可见）、悬浮卡片、弹窗；暗色模式改用边框和表面亮度区分层级。

### 3.5 图标与插图（UX-1.5）

- 图标：统一用一套线性图标（如 Lucide，npm 安装、按需引入），1.5px 描边，16/20/24 三种尺寸。替换现在的 emoji（🔑 👁）。
- 平台图标：YouTube、TikTok、Instagram，用于活动卡和提交，按各平台品牌规范使用。
- 插图：只在首页和空状态使用，几何风格、双色，与品牌色一致。

### 3.6 组件库（UX-1.6）

在 `web/src/ui/` 建立组件，所有页面只用这些组件：

| 组件 | 要点 |
|---|---|
| `Button` | primary / secondary / ghost / danger；sm / md / lg；加载态内置转圈并保持宽度 |
| `Input` / `AmountInput` | 前后缀（`XLM`、`/ 1k views`）；行内校验；帮助文字 |
| `Select`、`Segmented`、`Tabs` | 键盘可操作 |
| `Badge` / `StatusPill` | Live / Ending soon / Settling / Closed / On hold / Paid |
| `Avatar` / `Identicon` | 有头像用头像；没有时用地址生成的确定性渐变图案 + 首字母 |
| `AddressChip` | 头像 + 名称或缩略地址 + 复制 + 浏览器链接；悬停显示完整地址 |
| `Amount` | 统一格式化（千分位、小数位、单位、可选法币估值），等宽数字 |
| `Stat`、`ProgressBar`、`Sparkline` | 统计卡、预算进度、播放量趋势 |
| `DataList` | 桌面是表格，手机自动变卡片列表 |
| `Modal` / `Sheet` | 桌面居中弹窗，手机底部抽屉；沿用现有 `useDialog` |
| `Toast` | 成功 / 失败 / 进行中三种；可带"查看凭证"链接 |
| `TxProgress` | 交易四步：准备 → 签名 → 上链 → 确认，每步有状态和耗时 |
| `Skeleton`、`EmptyState`、`ErrorState` | 替代所有"Loading…"纯文本 |
| `Stepper` | 分步流程（建活动、提现） |
| `Tooltip`、`InfoHint` | 术语解释（如"什么是 passkey"） |
| `Timeline` | 提交的生命周期：提交 → 核验 → 付款 |

技术选择：继续使用手写 CSS + CSS 变量（不引入重型 UI 框架，保持包体小），组件用 React 写，样式按组件拆成 CSS Modules 或保持单文件但按组件分区。

## 5. 关键页面方案

### 5.1 首页（UX-2.2）

**目标：** 5 秒内说清"是什么、为谁、为什么可信"，并把两类用户分流。

```
┌─────────────────────────────────────────────────────────────────┐
│  Pay creators per verified view.          ┌────────────────────┐│
│  Budgets are locked on-chain and paid out │  产品画面：        ││
│  in seconds, anywhere.                    │  活动卡 + 实时到账  ││
│  [Launch a campaign]  [Find campaigns →]  │  动画（真实数据）   ││
│  ✓ No fees for creators ✓ Refund unspent  └────────────────────┘│
├─────────────────────────────────────────────────────────────────┤
│  实时指标：已锁定预算 · 已付给创作者 · 已核验播放 · 创作者数     │
│  （每个数字可点开链上凭证）                                     │
├──────────────────────────────┬──────────────────────────────────┤
│  For brands                  │  For creators                    │
│  只为真实播放付费…           │  Face ID 登录，几秒到账…          │
│  [Launch a campaign]         │  [Browse campaigns]              │
├──────────────────────────────┴──────────────────────────────────┤
│  How it works：三步，每步配图标 + 一句话 + 小插图               │
├─────────────────────────────────────────────────────────────────┤
│  正在进行的活动（3 张卡）  [查看全部 →]                          │
├─────────────────────────────────────────────────────────────────┤
│  信任区：资金托管在 Stellar 合约 · 开源 · 每笔付款可验证          │
│  [查看合约] [安全说明] [GitHub]                                  │
├─────────────────────────────────────────────────────────────────┤
│  FAQ（5 条）                                                     │
└─────────────────────────────────────────────────────────────────┘
```

验收：首屏出现产品画面；两类用户各有入口；指标可点开；手机端首屏不超过 1.5 屏。

### 5.2 活动市场 `/campaigns`（UX-2.3）

- 筛选：平台、类别、每千次报酬、截止时间、"还能参加"。
- 排序：最新、报酬最高、即将截止、剩余预算最多。
- **活动卡改版：**

```
┌───────────────────────────────────────┐
│ [品牌头像] Pixel Harbor  ✓            │
│ Tidewalker launch clips               │
│ [YouTube Shorts] [Gaming]             │
│                                       │
│ 0.80 XLM  / 1k views                  │
│ Earn up to 38 XLM                     │
│ ███████░░░░░  353 of 400 XLM left     │
│ 3 creators · Ends in 5d               │
└───────────────────────────────────────┘
```

- 不足 24 小时的活动显示"Ending soon"琥珀色徽标；预算低于 10% 显示"Almost full"。
- 空状态：插图 + "还没有符合条件的活动" + 清除筛选。

### 5.3 活动详情：创作者视角 `/c/:id`（UX-2.4）

**目标：** 回答三个问题：要做什么、能赚多少、怎么参加。

```
┌────────────────────────────────────────┬──────────────────────────┐
│ [头像] Pixel Harbor ✓  · Live · 5d left│  Join this campaign      │
│ Tidewalker launch clips                │  ┌────────────────────┐  │
│                                        │  │ Earn up to 38 XLM  │  │
│ [Brief] [Rules] [Leaderboard]  (tabs)  │  │ 0.80 XLM / 1k views│  │
│                                        │  │ you keep 95%       │  │
│ Brief：富文本简报 + 示例视频            │  └────────────────────┘  │
│ Rules：#ad、归属标签、时长等清单         │  1 Sign in with Face ID  │
│ Leaderboard：创作者排行（头像、播放、   │  2 Post with #ad + tag   │
│   已到账），每行可展开链上凭证          │  3 Paste your link       │
│                                        │  [Sign in & join]        │
│ 预算进度 · 已付 · 千次成本（次要位置）   │  资金已锁定在合约 ↗      │
└────────────────────────────────────────┴──────────────────────────┘
```

- 右侧参加卡在手机上变成底部固定按钮。
- 已参加时，右侧卡变成"我的提交"：时间线（Submitted → Verified 12,400 views → Paid 9.4 XLM）、暂缓原因及修复指引、下一次核验倒计时。
- "Verify views now"从公共视图移除：对创作者显示为"Refresh my views"，只刷新自己（受限流保护）；对品牌放在管理页。

### 5.4 活动管理：品牌视角 `/c/:id/manage`（UX-2.5）

- 头部 KPI：已花费、核验播放量、**实际千次成本**、参与创作者数、剩余预算与预计耗尽时间。
- 图表：每日花费和播放量（依赖事件索引 P1-B3，过渡期用当前快照）。
- 创作者列表：头像、帖子预览、播放量、已付、状态（含暂缓 / 复核原因），操作：查看帖子、标记争议（依赖 P1-C7）。
- 操作区：追加预算、复制分享链接 / 下载分享卡片、结束后退款（显示可退款时间倒计时）、导出 CSV。

### 5.5 建活动向导 `/new`（UX-2.6）

三步，每步一个主按钮，右侧始终显示实时预览卡：

1. **Brief**：活动标题、品牌名 + 头像、平台、类别、简报正文（Markdown 编辑器，替代必填外链；外链改为可选）、示例视频链接、规则清单（#ad 默认勾选）。
2. **Budget**：总预算、每千次报酬、每人上限、时长（日期选择器 + "7 天 / 14 天 / 30 天"快捷选项，替代"hours"）。实时计算器：最多可买的播放量、可覆盖的创作者数、创作者实得（扣除 5% 平台费）。余额不足时行内提示并给出"如何获取测试币"。
3. **Review & lock**：费用明细（预算、网络手续费估算、平台费说明：只从实际付款中收取）、退款规则、可读的条款摘要，然后签名。签名后用 `TxProgress` 展示四步进度，成功页提供"分享活动"和"查看活动"。

简报等链下元数据的存储依赖 P1-F7（R2 存 JSON，链上存 hash）。在它上线前，第 1 步的富文本先存在活动 brief URL 指向的托管页面里。

### 5.6 创作者中心 `/me`（UX-2.7）

```
┌──────────────────────────────────────────────────────────────┐
│ 余额 120.40 XLM   本月收入 +86.10   待核验 3 个帖子            │
│ [Cash out to bank]  [Send to address]                        │
├──────────────────────────────────────────────────────────────┤
│ 我的提交（DataList）                                          │
│ 活动 · 帖子 · 播放 · 已付 · 状态（Paid / On hold / Capped）   │
├──────────────────────────────────────────────────────────────┤
│ 收入记录（每笔付款 + 链上凭证）· 提现记录（anchor 状态）       │
├──────────────────────────────────────────────────────────────┤
│ 推荐活动（根据已参加的平台和类别）                            │
└──────────────────────────────────────────────────────────────┘
```

收入和提现历史依赖事件索引（P1-B3）。过渡方案：从当前合约状态汇总已付金额，提现记录存在浏览器本地。

### 5.7 钱包与提现（UX-2.8）

- 从下拉面板改为右侧抽屉（手机为底部抽屉），分三块：余额、操作、最近记录。
- 提现到银行改为 `Stepper`：金额（显示 anchor 限额、手续费、预计到账，接 SEP-38 报价后显示法币金额）→ 在 anchor 页面填写银行信息 → 确认转账 → 到账追踪。每一步说明正在发生什么、还要多久。
- 提现到地址：粘贴后校验地址类型；超过一定金额二次确认。

### 5.8 登录与引导（UX-2.9）

- 登录弹窗按角色分两条路径，配插图说明：创作者是"Face ID / Touch ID，无助记词，无手续费"，品牌是"连接钱包（Freighter，P1-F2 后支持更多）"。
- 首次创建 passkey 钱包后显示一次性说明：钱包在哪里、怎么提现、换设备怎么办（依赖 P2-7 恢复方案，先写清现状）。
- 用 `InfoHint` 解释 passkey、链上凭证、测试网等概念，不打断主流程。

## 6. 交互状态与反馈规范（UX-1.7）

| 场景 | 规范 |
|---|---|
| 首次加载 | 骨架屏，结构与最终内容一致；超过 8 秒显示"网络较慢"提示和重试 |
| 数据刷新 | 后台静默刷新，数字变化时短暂高亮（尊重 `prefers-reduced-motion`） |
| 交易 | `TxProgress` 四步；签名步骤说明"请在 Face ID / Freighter 中确认"；成功后 toast 带"查看凭证" |
| 表单错误 | 行内显示在字段下方，提交前校验；toast 只用于系统级错误 |
| 空状态 | 插图 + 一句解释 + 一个下一步按钮 |
| 错误页 | 404、活动不存在、网络错误分别设计，都给出返回路径 |
| 暂停维护 | 顶部横幅（已有），补充预计恢复时间和"退款仍可用"说明 |

## 7. 文案与术语（UX-1.8）

界面语言仍为英文（多语言见 P2-6）。统一术语表：

| 现在 | 改为 | 说明 |
|---|---|---|
| settle / settlement | **payout** / "Paid" | 用户只关心是否到账 |
| contract / CampaignPool | **escrow**（"Budget locked in escrow"） | 技术细节放在 `/security` |
| verifier | **view check** | "Views are checked every minute" |
| `G…`/`C…` 地址 | 名称或头像 + 缩略地址 | 完整地址只在悬停和复制时出现 |
| `0.8 XLM / 1k views` | `0.80 XLM per 1,000 views` | 详情页可以写全；卡片保留简写 |
| passkey wallet | **Face ID wallet**（首次出现时解释 passkey） | 用户能理解的叫法 |
| On hold | On hold + 原因 + 怎么修 | 永远给出下一步 |
| tx hash | "View receipt" | 链上凭证统一叫 receipt |

语气：简短、具体、主动语态；按钮用动词开头（"Lock budget & launch"、"Join campaign"）。

## 8. 信任与专业感要素（UX-2.10）

- **资金托管徽标**：活动页显示"Budget locked in escrow · View contract"，链接到区块浏览器。
- **链上凭证**：每笔付款、每次退款都有"View receipt"。
- **品牌认证**：品牌通过域名验证后显示 ✓（方案：品牌在自己域名放置 `stellar.toml` 或 DNS TXT，对应 SEP-1 思路；先做人工审核标记）。
- **透明数据**：首页实时指标，`/security` 页面列出合约地址、Wasm hash、可验证构建（依赖 P1-C10）、审计状态、信任模型。
- **测试网标识**：常驻徽标 + 首次访问提示。
- **完整的页脚和法律页**：关于、条款、隐私、联系方式。
- **演示数据标注**：虚构品牌在活动卡上标注"Demo"，避免误导。

## 9. 响应式与无障碍（UX-1.9）

- 断点：≤ 480（手机）、481–768（大屏手机 / 小平板）、769–1200（平板 / 笔记本）、> 1200。
- 手机优先：创作者路径（市场 → 详情 → 参加 → 我的收入）按手机设计，桌面再扩展。
- 表格在手机上自动变卡片列表（`DataList`）；弹窗变底部抽屉；主操作固定在底部。
- 触控目标 ≥ 44px；字体最小 13px。
- 继续保持 axe 0 个 serious/critical；新增：`prefers-reduced-motion`、跳到主内容链接、表单错误关联 `aria-describedby`、图表提供文字摘要。

## 10. 性能（UX-3.1）

| 项 | 方案 | 目标 |
|---|---|---|
| 首屏 JS | 钱包（smart-account-kit、Freighter）、anchor、交易构建按需加载：登录或点击操作时才加载 | 首屏 JS ≤ 200 KB（gzip） |

## 13. 如何衡量

- **可用性测试**：每个阶段结束后，品牌和创作者各找 5 人做任务测试。任务：找到值得做的活动并参加；建一个 100 预算的活动；把收入提现。记录完成率、耗时、出错点。
- **5 秒测试**：首页给 10 人看 5 秒，回答"这是什么、给谁用"，目标 8/10 答对。
- **漏斗数据**（Cloudflare Web Analytics，不使用第三方追踪）：访问 → 登录 → 首次提交 → 首次到账 → 提现；品牌：访问 → 开始建活动 → 签名成功。
- **质量门槛**：axe 0 个严重问题；Lighthouse 性能 ≥ 85、无障碍 ≥ 95；视觉回归截图（Playwright，依赖 P1-F9）。

## 14. 取舍与风险

| 取舍 | 决定 | 理由 |
|---|---|---|
| 引入 UI 框架（如 Tailwind、组件库） vs 手写 | 手写 CSS 变量 + 自建组件 | 包体小，现有代码已有 token 基础；后续需要时再评估 |
| 首页和应用分开部署 | 暂不分开 | 同一个 Worker 足够；营销页按路由懒加载 |
| 演示数据的"真实感" | 标注 Demo，不用真实品牌名和 logo | 避免误导和侵权 |
| 赛前改动范围 | 只做 UX-0 | 结构性改版风险高，留到赛后 |

风险：赛前改动可能引入回归。缓解：UX-0 每项单独提交，提交前跑 axe、手机截图和线上冒烟测试（首页、详情、提交、建活动）。
